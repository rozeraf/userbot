# Userbot Workspace

`Userbot Workspace` — приватный Telegram supergroup-форум, который tg-userbot создаёт и обслуживает автоматически. Он дополняет обычные `.commands` отдельным интерфейсом внутри Telegram.

## Топики и маршрутизация

| Топик | Поведение |
|---|---|
| `Chat` | Обычный исходящий текст без `.` выполняется как durable `workspace_chat` и получает LLM-ответ. `.commands` работают как обычно. |
| `Saved` | Тихое хранилище: сообщения журналируются, но не вызывают команды и ответы. |
| `Media` | Тихое хранилище для медиа и подписей. |
| `Settings` | Настройки юзербота: явные `.commands` работают, обычный текст только сохраняется без LLM-ответа. |
| `System` | Warn/error события и служебные уведомления tg-userbot. Пользовательский текст не вызывает ответ. |

Вне workspace юзербот по-прежнему отвечает только на сообщения с `COMMAND_PREFIX` (`.`). Router сравнивает Telegram `chatId` и forum topic ID; названия используются только как отображаемые метаданные.

## Инициализация

При первом авторизованном запуске бот:

1. создаёт приватный megagroup с forum mode;
2. переименовывает General topic в `Chat`;
3. создаёт `Saved`, `Media`, `Settings` и `System`;
4. сохраняет channel identity, access hash и topic ID в `app_meta.workspace_config_v1`.

При следующих запусках channel восстанавливается по сохранённым ID. Существующие topic ID проверяются через Telegram API; создаются только отсутствующие топики. `randomId` сохраняется до вызова создания, а фактический topic ID берётся из Telegram Updates и записывается сразу после успеха.

Если Telegram временно недоступен, workspace initialization логирует ошибку, но основной command-only userbot продолжает запуск. Transient validation errors не считаются удалением топика и не запускают создание дубля.

## Проверка

- Написать обычный текст в `Chat`: должен появиться LLM-ответ в том же топике.
- Написать текст или `.status` в `Saved`/`Media`: ответа быть не должно.
- Выполнить `.status` вне workspace: команда должна работать.
- Перезапустить service и проверить строку `[workspace] ready` с теми же topic ID.

Конфигурацию в `app_meta` нельзя редактировать вручную без одновременной проверки Telegram channel identity. Удаление записи приведёт к созданию нового workspace.
